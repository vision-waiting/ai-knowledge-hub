# AI Knowledge Hub 前端展示优化方案

编写日期：2026-09-29  
适用范围：`vue/` 前端；本文为待实施方案。

实施进展：2026-09-30 已落地本轮前端优化，具体改动、验证结果与边界见 [实施记录](frontend-display-implementation.md)。下文保留原方案作为验收依据。

## 1. 优化目标与现状

围绕“进入知识库 → 阅读资料 → 提问并核验引用 → 保存和复习”的使用路径，让用户更快找到入口、看懂处理状态和阅读结果。保留现有深绿色品牌与 Vue 3、Element Plus 技术栈，优先改善信息组织和阅读体验。

本方案依据源码和项目说明编写，尚未进行浏览器实测；以下“现状”是代码观察，“建议”是设计目标，性能、对比度及具体屏幕溢出情况需在实施时测量。

| 代码观察 | 对展示的影响 | 优化方向 |
| --- | --- | --- |
| `AppLayout.vue` 将 13 个普通入口平铺，工作台排在第 6 项，另有 3 个管理入口 | 核心与辅助功能缺少层级，短屏下导航可用空间紧张 | 工作台置顶，按任务分组，导航区独立滚动 |
| 首页依次呈现标题、宣传横幅、知识库和统计 | 首屏可操作内容受横幅占用影响 | 缩短介绍，把知识库和继续工作入口前移 |
| `main.ts` 依次加载 `styles.css`、`workspace.css`、`tools.css`，前两者重复定义主题、侧栏及内容尺寸 | 调整主题和断点时容易产生跨文件覆盖 | 统一设计变量，逐步明确样式归属 |
| 聊天已有会话栏、流式回答、停止按钮和引用抽屉 | 已具备完整交互，重点应放在阅读与状态反馈 | 强化回答和引用层次，核对滚动及小屏体验 |
| 搜索要求先选知识库；多个工具页面也需要资料上下文 | 跨页操作可能增加重复选择成本 | 从知识库进入工具时携带上下文，保留清晰的范围提示 |
| 已有移动端规则、焦点样式、空态及错误提示 | 可在已有基础上统一规范 | 按场景补齐，避免重复建设 |

## 2. 导航与信息架构

保留现有路由，第一阶段只调整入口分组和标签，不改收藏链接及业务权限。

| 分组 | 入口及现有路由 | 呈现方式 |
| --- | --- | --- |
| 常用 | 工作台 `/dashboard`、知识库 `/knowledge`、全文搜索 `/search`、聊天记录 `/chat/history` | 默认展开，工作台置顶 |
| 学习与整理 | 总结与对比 `/analysis`、学习助手 `/study`、复习计划 `/review-plan`、个人笔记 `/notes` | 分组显示，支持折叠 |
| 内容维护 | 知识内容与维护 `/workspace`、网页资料 `/web-sources`、检索评测 `/retrieval` | 分组显示，保留普通用户现有可访问能力 |
| 管理 | 用户管理、操作日志、统计分析 | 继续按管理员身份显示 |
| 顶部与账号区 | 更新提醒 `/notifications`、个人中心 `/profile` | 提醒由顶部铃铛进入，个人中心由账号区进入 |

导航激活态同时使用背景、文字和左侧标识。父分组折叠时，进入其子页面应自动展开。知识库子页顶部展示“知识库 / 库名称 / 文档或问答”等准确位置，避免所有子页面只显示“知识库”。

知识库详情作为上下文入口，集中提供文档、问答、总结、学习和内容维护。已支持路径参数的工具沿用原路径；查询参数只在目标页面校验并支持后使用。切换知识库时清理旧结果与原文引用，防止资料范围混淆。

## 3. 视觉与布局规范

视觉方向：深绿侧栏、浅灰绿画布、白色内容卡片。主色用于主按钮、当前导航和关键链接；红色只表达失败及危险操作。优先用留白、字号和边框划分层次。

以下为建议初值，实施后以实际屏幕和对比度检查调整：

| 项目 | 建议规范 |
| --- | --- |
| 色彩 | 主色 `#247B69`，侧栏 `#132F29`，页面 `#F4F7F6`，正文 `#253C35`，次要文字 `#566860`，边框 `#E2E8E6` |
| 字体 | 继续使用系统中文字体；页面标题 26–28px，分区标题 18–20px，正文 14–16px，辅助信息 12–13px |
| 阅读 | 问答与原文建议 16px、1.75–1.9 行高；正文宽度约 760–840px；表格及代码块独立横向滚动 |
| 间距 | 使用 4、8、12、16、24、32、48px；卡片内边距 20–24px，移动端 16px |
| 圆角 | 输入框和按钮 8px，卡片 12px，重点容器不超过 16px |
| 阴影 | 主要用于浮层；普通内容卡片默认以边框区分，悬停轻微增强 |
| 操作 | 一个区域突出一个主操作；次要操作用描边或文字按钮，低频操作放入“更多” |
| 反馈 | 轻量颜色过渡约 150–200ms；遵循减少动态效果偏好，无须新增动画依赖 |

页面布局根据可用内容宽度切换，而非只按设备名称判断：

| 视口宽度 | 页面策略 |
| --- | --- |
| ≥1280px | 侧栏约 232px，内容最大宽度约 1440px；知识库通常三列，宽屏可增加列数 |
| 768–1279px | 侧栏可收起；卡片一至两列；工具结果优先占据完整内容宽度 |
| <768px | 侧栏变抽屉，内容单列、16px 留白；筛选折叠，原文全屏展示 |

320px 宽度仍须保证主操作可达。普通页面不允许整体横向滚动；确有需要的表格和代码区域可单独滚动。聊天输入区考虑软键盘和安全区，不能遮住最后一条回答。

## 4. 核心页面优化

### 4.1 工作台：从宣传入口转为工作入口

首屏顺序调整为：标题与新建操作 → 紧凑统计 → 可访问知识库 → 继续工作；详细图表放在下方。宣传横幅改为一行说明，首次空账号展示创建指引。

桌面布局示意：

```text
┌──────────┬───────────────────────────────────────────┐
│ 品牌     │ 当前位置                    服务状态  提醒 │
│ 常用     ├───────────────────────────────────────────┤
│ 工作台   │ 知识工作台                    [新建知识库] │
│ 知识库   │ 紧凑统计：仅使用现有接口支持的账号数据     │
│ 全文搜索 │                                           │
│ 聊天记录 │ 我的知识库                      [查看全部] │
│          │ [库名称 / 描述 / 文档数 / 开始问答] × 3    │
│ 学习整理 │                                           │
│ 内容维护 │ 继续工作：近期会话、学习或笔记入口         │
│          │ 详细统计                                  │
│ 账号     │                                           │
└──────────┴───────────────────────────────────────────┘
```

“最近使用”“待处理”等数据不能用随机数或静态值填充。第一版继续展示现有接口返回的知识库及统计；近期记录仅在确认接口支持筛选、排序和权限后接入，否则先提供聊天记录、复习计划等快捷入口。

### 4.2 知识库列表与详情：突出资料范围和下一步

- 列表保留个人/共享切换，统一卡片高度和操作位置；库名称最多两行，描述最多两行，完整内容在详情查看。
- 卡片突出名称、共享属性、已有文档数量和“开始问答”；编辑、删除移入更多菜单，并继续遵循权限判断。
- 详情页顶部保留库名称、描述和关注更新，主操作为“开始问答”，文档管理为次操作。
- 可检索、处理中、失败数量使用文字及状态标签区分；失败数量可进入文档列表对应筛选，须先补齐目标页筛选参数支持。
- 无可检索资料时说明原因；有写权限时引导上传或处理资料，只读用户看到“暂无可检索资料”，不展示无法使用的上传入口。

### 4.3 文档管理：让处理进度可理解

工具栏顺序统一为“搜索 → 状态筛选 → 刷新”，上传位于标题主操作区。桌面表格优先展示名称、状态、更新时间及操作；摘要作为次级信息展开，避免单行高度失控。

上传传输进度与解析/索引状态分别显示。解析没有真实百分比时使用“处理中”，失败提供原因和可执行的重试操作。已有上传、索引、版本及回收站行为保持兼容，不为展示改动增加未经验证的后端状态。

小屏将主要信息改为文档卡片，或保留有明确滚动提示的精简表格。版本与回收站入口保持可发现，删除确认明确说明实际删除或回收行为。

### 4.4 智能问答：回答清晰，证据易查

- 顶部持续展示当前知识库及实际服务模式；详细模型和向量信息放入状态说明。
- 新会话展示少量可直接编辑的问题示例；示例作为提问建议，不暗示资料中必有答案。
- 回答采用清晰段落和标题层级；保留复制、保存笔记、反馈等已有功能，操作区与正文分隔。
- 引用以编号和文档名呈现，点击复用 `SourceDrawer.vue` 查看对应原文片段；引用编号必须与当前回答一致。
- 保留生成中、停止、失败、历史加载状态；停止后保留已生成内容，重试沿用当前资料范围。
- 仅在用户靠近消息底部时自动跟随；阅读上文时显示“回到最新”按钮，避免流式输出抢滚动位置。
- 桌面保留会话侧栏；小屏复用或改善已有会话选择入口，原文抽屉占满屏幕。关闭后焦点回到引用按钮。

### 4.5 搜索与学习工具：统一操作顺序

全文搜索维持当前知识库范围，不将现有能力包装成跨库搜索。上方显示范围、关键词和筛选，下方按“文档名 → 命中片段 → 来源 → 查看原文”呈现结果。保留关键词高亮和分页，空结果提示用户修改关键词或筛选条件。

总结、对比、学习助手统一为“选择资料 → 设置目标 → 执行 → 阅读结果”。宽屏可采用左侧设置、右侧结果，小屏改为上下排列。生成过程中保留选择，失败可重试；资料数量限制及实际覆盖范围沿用后端能力。

AI 生成、原文摘录和本地练习使用准确标签。生成结果、练习记录、个人笔记和复习计划通过已有入口衔接；只把已成功保存的内容显示为“已保存”。

## 5. 状态、权限与可访问性

| 场景 | 展示约定 |
| --- | --- |
| 首次加载 | 为卡片或列表保留骨架占位，避免先显示空态再闪现内容 |
| 刷新 | 保留已有数据，刷新按钮显示进度；失败时标明旧内容未更新 |
| 无内容 | 解释当前范围，并给出与权限匹配的下一步 |
| 无搜索结果 | 显示当前搜索条件，提供修改关键词或清空筛选 |
| 请求失败 | 区域内说明失败原因并提供重试，避免静默显示为 0 或空列表 |
| 无权限 | 说明不可访问，提供返回入口；界面隐藏不能代替后端鉴权 |
| 长文本 | 名称允许换行或截断后查看完整值；Markdown 表格、代码不撑破页面 |

所有图标按钮提供可访问名称；键盘可以打开导航、筛选、操作菜单与原文抽屉。弹窗和抽屉管理焦点，关闭后恢复原位置。状态不能只依赖颜色，流式回答避免逐字向读屏器重复播报。实施时测量正文对比度，目标至少 4.5:1；重点移动端按钮触控区域建议不小于 44×44px。

性能处理先记录基线再调整：保留已有路由懒加载，检查图表是否可以延迟挂载，长列表优先使用既有分页。虚拟列表、缓存和额外拆包仅在实际测量显示必要时引入；不能通过隐藏报错或展示旧数据冒充提速。

## 7. 实施顺序与工作量

以下为单名前端开发的初步估算，包含页面联调和验证，不包含新增后端接口；实际排期需结合当前未提交改动确认。

| 阶段 | 优先级 | 交付内容 | 估算 |
| --- | --- | --- | --- |
| 基线 | P0 | 记录代表性页面截图、主要状态、接口字段和现有测试结果 | 0.5 天 |
| 布局基础 | P0 | 导航、主题变量、页面间距、移动端壳层 | 1–1.5 天 |
| 核心页面 | P0 | 工作台、知识库、文档、问答与引用 | 2–3 天 |
| 工具一致性 | P1 | 搜索、总结、学习、笔记及提醒的共同展示规则 | 1–2 天 |
| 验收修正 | P0 | 响应式、权限、异常状态和既有行为回归 | 1 天 |

预计合计 5.5–8 个工作日。第一批可先交付布局基础及核心页面。最近使用聚合、新统计指标或跨库搜索如需要新增接口，另列需求，不作为本轮展示优化的隐含工作。

## 8. 验收标准

1. **任务入口**：登录落在工作台；工作台中已展示的知识库可一次点击进入问答；提醒和个人中心移动后仍可直接访问。所有原有路由可用。
2. **响应式**：在 1440×900、1280×720、768×1024、390×844、320×568 检查工作台、文档和聊天；无页面级横向溢出，导航和输入区操作不被遮挡。
3. **资料可信**：统计来自真实接口；请求失败不显示为有效的 0；回答引用打开正确文档和片段；不同服务模式与资料覆盖范围有准确说明。
4. **关键交互**：上传到处理完成、处理失败重试、发送/停止回答、历史会话恢复、引用查看、保存笔记和搜索分页通过回归。
5. **权限场景**：普通用户、库维护者、只读共享访问者和管理员分别检查；个人笔记及会话隔离不受展示改动影响。
6. **可访问性**：仅键盘可完成主要流程；焦点可见；抽屉关闭可恢复焦点；状态有文字说明；检查中文输入法回车不会误发消息。
7. **工程验证**：在 `vue/` 执行 `npm run build` 和 `npm run test -- --run`；新增测试针对导航激活、资料范围保持、焦点恢复等行为，不断言无意义的 CSS 类名。
8. **视觉回归**：同一账号、同一数据与视口保存前后截图，覆盖空态、正常数据、长名称、加载和错误；对照检查字体、留白、卡片及抽屉。
9. **性能对照**：同一设备、网络配置与数据量下，各记录至少三次关键页加载和交互，比较中位数；如耗时增加超过约 10%，排查后再接受。该阈值为项目建议目标，当前未测量。

本次交付为方案文档。页面改造、浏览器验收和上述性能测试待实施阶段执行。
