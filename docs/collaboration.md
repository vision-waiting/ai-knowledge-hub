# 知识库共享与协作

## 使用入口

- 知识库列表：新建和编辑时选择共享范围；所有账号默认创建私有库，管理员也可撤回公开。通过「我的收藏」筛选收藏的库。
- 知识库详情：收藏、复制分享链接、关注更新。公开指对所有**登录用户**可读，分享链接本身不会赋予权限，也不是匿名访问令牌。
- 知识内容与维护：在 FAQ、术语、阅读路线条目下点击「建议修改」或「版本历史」；「修改建议」页签列出待审核、已合入、已关闭的建议。
- 管理者查看修改前后的标题和 Markdown 正文，然后合入或关闭；作者也可撤回自己的待审核建议。建议和审核记录对当前有阅读权限的人可见。

## 版本与权限

每条内容有递增版本号。提交建议和直接编辑时携带看到的版本号 `baseVersion`；直接编辑、建议提交和合入都检查版本，过期返回 409，避免覆盖后来更新。编辑冲突时保留草稿，请先复制草稿，再查看最新内容并重新编辑。直接编辑接口缺少版本号返回 400，旧客户端需要同步更新；新增条目不要求版本号。直接编辑、合入、恢复都会保存快照；恢复生成新版本而不是改写历史。历史界面展示最近 100 个版本。迁移前的内容作为初始快照保留，历史操作者未知时不虚构身份。

合入记录贡献者和审核者，合入与恢复在事务提交后通知关注者。收藏不等于关注，不发送通知。知识库撤回共享、移除成员或删除后，建议、历史、收藏列表和通知会按当前权限过滤；用户仍可取消自己的收藏。

此首版的修改建议针对人工维护的知识条目（FAQ、术语、阅读路线），只修改标题和正文。附件文档沿用现有上传新版本、历史下载及回收站流程。条目不会自动加入 RAG 索引。Fork、上游同步、匿名分享、附件修改建议与通用 Issue 讨论不在本次范围内。

## API

以下接口均需登录，路径前缀为 `/api/knowledge-bases/{kb}`。

| 方法与路径 | 用途 |
| --- | --- |
| GET /star | 当前账号收藏状态及收藏人数 |
| PUT /star | 收藏，重复请求幂等 |
| DELETE /star | 取消本人收藏，失去阅读权限后也可调用 |
| GET /suggestions?status=OPEN&offset=0 | 按状态分页，每页 20 条，返回 items / hasMore |
| POST /suggestions | 提交 contentId、baseVersion、title、body、reason |
| POST /suggestions/{id}/merge | 管理者审核合入；已处理或版本冲突返回 409 |
| POST /suggestions/{id}/close | 管理者关闭或作者撤回 |
| GET /content/{id}/history | 最近 100 个版本、快照及贡献记录 |
| POST /content/{id}/history/{version}/restore | 管理者恢复为新的当前版本 |

知识库列表与详情增加 `starred`、`starCount`。内容条目增加 `version`。`sharingLocked` 为兼容旧客户端保留，始终为 false。

## 数据与验证

启动时增量创建 `knowledge_star`、`content_suggestion`、`content_revision`，并给 `knowledge_content` 添加 `version`（默认 1）。不删除原数据、不重写已有 `shared` 值。完整建表在 `sql/schema.sql` / `sql/init.sql`，独立新增表脚本在 `sql/collaboration.sql`。

内容更新先锁内容行，再检查/递增版本；审核状态和基线存在性使用锁定读取，避免 MySQL REPEATABLE READ 下的旧快照。测试覆盖权限隔离、重复收藏、冲突合入、历史恢复、跨库建议、输入验证和锁定读取语义。浏览器验收可使用隔离的 test profile 内存数据库；该预览数据不持久化，也不代表对真实 MySQL 并发的实测。
